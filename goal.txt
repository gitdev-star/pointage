testing for CI/CD

FastAPI (runs on the host directly):
bashmake test-fast
# or directly:
pytest tests/ -q
django_auth (runs inside its container):
bashdocker exec django_auth bash -c "cd /app && python -m pytest tests/ -v"
django_hr (runs inside its container):
bashdocker exec django_hr bash -c "cd /app && python -m pytest tests/ -v"
Run all three at once:
bashpytest tests/ -q && \
docker exec django_auth bash -c "cd /app && python -m pytest tests/ -v" && \
docker exec django_hr bash -c "cd /app && python -m pytest tests/ -v"
Or if your Makefile has targets for all three, check with:
bashcat Makefile | grep "^test"

Makefile Commands - Quick Reference
Run any of these from your project root:


make test              # Run all tests with coverage
make test-fast        # Quick test run (no coverage)
make test-cov         # HTML coverage report
make test-all         # Verbose output
make test-unit        # Unit tests only
make test-integration # Integration tests only
make test-fastapi     # FastAPI app tests
make test-auth        # Django Auth tests
make test-hr          # Django HR tests
make test-debug       # Verbose + full traceback
make test-pdb         # Drop into debugger on failure
make coverage-html    # Generate & open coverage report
make lint             # Check code with flake8
make format           # Auto-format with black


What pytest.ini Does
Sets up async test mode for FastAPI
Marks tests as @pytest.mark.unit or @pytest.mark.integration
Requires 70% code coverage
Auto-generates HTML coverage reports in htmlcov/
Common Workflows
Quick test during development:


make test-fast

Full check before committing:


make test-cov

Debug a failing test:

make test-pdb


Check one service:

make test-fastapi    # or test-auth, test-hr
